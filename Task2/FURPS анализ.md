
Анализ требований для планирования цифровой трансформации банка
# FURPS+ выявление требований

| Код         | Требования                                                                  | Комментарий                                                       |
| ----------- | --------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| **F**       | **Функциональные (Functionality)**                                          |                                                                   |
| F1          | Подача заявки на депозит через сайт                                         |                                                                   |
| F2          | Подача заявки на депозит через интернет-банк                                |                                                                   |
| F3          | Персонализированные ставки для клиентов интернет-банка                      |                                                                   |
| F4          | Автоматическая передача заявок с сайта в систему кол-центра                 |                                                                   |
| F5          | Централизованное управление ставками в АБС (вместо Excel)                   | Критично для устранения ручных процессов                          |
| F6          | Механизм согласования "специальных ставок" между отделами в АБС             |                                                                   |
| F7          | СМС-уведомления клиента на ключевых этапах (подтверждение ставки/открытие)  |                                                                   |
| **U**       | **Удобство использования (Usability)**                                      |                                                                   |
| U1          | Единый дизайн-система для всех интерфейсов (сайт, ИБ, мобильное приложение) | Соответствие бренд-буку                                           |
| U2          | Время отклика интерфейсов < 500 мс для всех операций                        |                                                                   |
| U3          | Адаптивные интерфейсы для мобильных устройств                               | Большинство пользователей используют именно мобильные устройства  |
| U4          | Удобное и понятное отслеживание статуса заявки для клиента                  | Обеспечит снижение количества обращений в кол-центр               |
| **R**       | **Надёжность (Reliability)**                                                |                                                                   |
| R1          | Доступность 99.9% для интернет-банка и сайта                                |                                                                   |
| R2          | Автоматическое переключение на резервный ЦОД при сбое (режим стнендина)     | Не реализовано в текущей архитектуре                              |
| R3          | Гарантированная доставка заявок между системами (сайт → CRM → АБС)          | Может помочь механизм очередей                                    |
| R4          | Защита от потери данных при обработке заявок                                | Обязательная транзакционность критичных операций                  |
| **P**       | **Производительность (Performance)**                                        |                                                                   |
| P1          | Горизонтальное масштабирование веб-сервисов интернет-банка                  | Текущая архитектура не поддерживает                               |
| P2          | Асинхронная обработка длительных операций                                   | Чтобы не блокировать UI                                           |
| P3          | Кэширование справочников и статических данных                               | Для устранения задержек                                           |
| **S**       | **Поддерживаемость (Supportability)**                                       |                                                                   |
| S1          | Использование существующих технологий (MS SQL/Oracle)                       | Для минимизации обучения текущей команды                          |
| S2          | Документирование всех интеграций и API                                      |                                                                   |
| S3          | Логирование ключевых событий для аудита                                     |                                                                   |
| S4          | Возможность расширения на кредитные продукты                                | Архитектурное требование                                          |
| **+R**      | **+ Ограничения (Restrictions)**                                            |                                                                   |
| R1          | Запрет прямой интеграции интернет-банка с API АБС                           | Из-за риска перегрузки АБС                                        |
| R2          | Шифрование трафика для всех передач ПДн                                     | Требование ФЗ-152                                                 |
| R3          | Реализация без доработок ядра интернет-банка подрядчиком                    |                                                                   |
| R4          | Вертикальное масштабирование базы данных АБС                                | Ограничение архитектуры Oracle                                    |
| R5          | Совместимость с текущими платформами (.NET 4.5, Java 8)                     | Экспертиза команд                                                 |
